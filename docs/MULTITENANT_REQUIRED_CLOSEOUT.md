## 同机共享数据调整

平台和同机默认企业采用一个 PostgreSQL 分库、一个 Redis 分编号（平台 DB0、企业 DB1），
不增加 Redis ACL 用户和新键前缀。其他企业保持独立实例。配置生成、本机受控迁移、企业
按库备份/新库恢复已实现，本机运行与隔离恢复演练通过，证据见阶段 41；操作入口见
[同机共享部署说明](MULTITENANT_SHARED_HOST.md)。
真实主机与原域名发布仍待环境验证，不改变 R7 外部验收边界。

## 本轮固定约束

1. R2 采用人工维护窗口与受控工具；没有自动故障切换或不停机恢复。原库/原卷保留，证据变化或审计失败保持隔离。
2. R3 要求升级客户端；取消旧版 App 继续使用业务的认证兼容层。自动回退只允许新环境正式开放写入之前，开写后走停写和受控恢复。
3. R4 异常由运维处理；不新增通用任务取消、自动补偿或自动释放账号功能。
4. R5 移动端由企业向平台提交受控请求，再由平台统一调用个推；企业不持有供应商凭据或设备令牌。未配置/未就绪的 VoIP 明确不可用。
5. R6 不新增跨账号续传、跨设备草稿同步；保留原身份范围内已有恢复行为。
6. 不自动提交、推送、改 App 版本、购买资源、迁移真实账号、签名发布安装包或部署现网。
