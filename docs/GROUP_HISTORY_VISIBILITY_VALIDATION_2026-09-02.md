# 群历史消息可见性：实现与验证

日期：2026-09-02。工作环境：Windows / PowerShell 7.6.4。

## 已实现

- 数据库版本 58：`im_groups.history_visible_to_new_members=false`、`history_policy_version=1`；`im_members.history_after_seq` 可空。
- 现有群和新群默认关闭。建群初始成员边界为 0；旧成员使用原 `joined_at` 的秒级严格边界，同秒消息保守隐藏。
- 邀请接受、直接添加、扫码入群均在同一事务保存成员、WuKong 最大序号边界及 Outbox。获取边界失败返回 503，不创建零边界成员；重复加入保留原边界，退出重入重新读取。
- 并发入群以 WuKong 最大序号读取结果为线性化边界：该快照之前的消息不可见，快照之后的消息可见，不使用客户端时间判断。
- `im_can_read_group_message` 与统一消息同步适配器限制普通用户的分页、搜索、详情/转发源、扩展/编辑记录、置顶、收藏、提醒和附件。群主/管理员读取时不豁免。
- 后台审核历史仍使用独立授权路径并保留原查看审计，不套用成员入群边界。
- 开放旧历史不增加历史未读；关闭后过滤最近会话摘要和提醒。策略修改与审计、持久通知一并提交，重复值不递增版本。
- App 群资料 GET/PATCH 返回 `historyVisibleToNewMembers` 和服务端计算的 `historyAccess`；后台新增 `PUT /v2/admin/groups/{id}/history-visibility`，要求 `groups.write`、`confirmed` 和理由。
- App「群聊资料与管理 → 历史消息」增加开关，普通成员只读。后台「群组详情 → 资料」增加同名开关与确认弹窗。保留现有主题和布局。

## 客户端缓存边界

- Android、iOS、Web、macOS 共享策略解析、消息过滤和加密缓存清理逻辑。
- 策略关闭时立即通知控制器，清理不可见消息、搜索结果、收藏/置顶显示和引用定位入口，再处理持久缓存。
- 以策略版本阻止旧响应覆盖新通知；相同版本的旧入群边界不能覆盖重新入群后的边界。
- 断线后不继续信任之前的群历史策略；重新连接先刷新策略。冷启动未知群策略时，不展示旧群消息快照。
- Android/iOS SDK 本地数据库删除越界缓存行及相关扩展/提醒，**不调用 SDK 消息墓碑删除、不撤回、不删除服务器消息**。SDK 初始化后再次执行清理，以覆盖策略先于数据库初始化的情况。
- Web SDK 清理内存最近会话预览和提醒；macOS Easy SDK 没有独立持久消息库，使用统一业务缓存。
- 保留本地发送中、失败消息和输入草稿；开放后重新从 WuKong 拉取可见消息。
