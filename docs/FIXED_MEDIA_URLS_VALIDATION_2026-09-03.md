# 固定媒体地址与登录鉴权

## 结果与范围

图片、视频、视频封面及文件改用固定业务地址，不再让新版客户端在每次查看时先请求对象存储签名 URL。固定地址不是公开链接：读取仍要求有效登录会话，并检查账号状态、附件权限及群历史可见范围。

本次保留已有未提交的视频完善和 PC 登录 IP 修改；不提交、推送、部署、不构建 APK/IPA、不修改版本或强制更新策略。此项改动本身无需数据库迁移，前一项视频封面功能的数据库版本 61 仍需随发布执行。

## 访问方式

- `GET/HEAD /v2/media/{id}/content`：直接读取附件字节。
- `GET/HEAD /v2/media/{videoId}/cover`：以原视频权限读取其已绑定的封面。
- `POST /v2/media/session`：恢复登录时补发媒体凭据、修复 Web 媒体 Cookie，不在每次读取附件时调用。
- 地址只有稳定媒体 ID 和本地使用的 `viewer` 账号隔离参数，没有 Token、签名或过期时间；发送到 WuKongIM 的地址不包含 `viewer`。
- 原生播放器、图片和下载请求使用仅能读取媒体的 `Authorization: Media …`；Web 视频元素使用限定 `/v2/media/` 路径的 HttpOnly Cookie。普通业务接口不接受这两种媒体凭据。
- 登录与刷新时更新媒体凭据，其有效期随登录会话配置，不依赖短期对象 URL。每次媒体请求重新检查设备会话，因此退出、会话替换及账号封禁仍可拒绝访问。
- 明确提供无效 Authorization 时不回退 Cookie；客户端不向外部地址附加媒体凭据。切换账号后丢弃迟到的下载结果，媒体缓存按账号地址区分。

“固定”不表示文件永久保留，也不表示无需登录。文件不存在、权限撤销或登录过期时仍可能无法读取。已经下载的副本无法回收，旧签名链接也不会被本次改动提前作废。

## 服务端与客户端行为

- MinIO 继续使用私有桶，Go 按权限直接流式读取，响应不重定向到签名地址。
- 支持完整下载、HEAD、字节范围 206、非法范围 416、ETag 和条件读取；视频保持真实 MIME 及 inline 语义。使用可重置的空闲写超时，避免普通 API 的 30 秒总写超时中断仍在传输的大视频。
- 响应为 `private, no-cache, must-revalidate`，避免共享缓存绕过权限；本地既有媒体缓存仍可复用。新地址减少的是“获取签名 URL”的额外请求，不是取消必要的媒体读取和权限校验。
- 新版按媒体 ID 将历史签名 URL 转换为固定地址，图片气泡、图片预览、视频、封面、文件下载及语音读取接入同一媒体访问上下文；本地草稿和 Blob 预览保持原样。
- 媒体绑定继续执行原有权限接口，上传仍使用短期预签名上传地址。旧客户端及后台原有 `/url` 兼容接口仍保留，未将所有调用者强制切换。
- Web 正式使用同源部署（当前 `/app` 与 `/v2` 代理模式）；精确允许的跨域 API 支持凭据 CORS。任意跨站部署受浏览器第三方 Cookie 限制，不能承诺跨站 Web 视频可用，应提供同源代理。
- 附件字节会经过 Go 服务，增加业务服务的网络与长连接负载；本轮未做吞吐量压测，不宣称与对象存储直连性能相同。

## 发布建议

先备份并更新服务端（包含前一项版本 61 迁移），再更新 Web 和移动/桌面客户端。旧客户端继续走兼容签名接口；完整固定地址行为需要新版客户端。部署 Web 时保持 API 同源，并在真机抽测图片、语音、视频及下载。
