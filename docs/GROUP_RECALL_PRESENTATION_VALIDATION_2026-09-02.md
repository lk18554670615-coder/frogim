# 群消息撤回权限与管理提示：实现与验证

日期：2026-09-02；Windows / PowerShell 7.6.4。

后续同日调整：私聊撤回已独立为 `directRecallMinutes`，默认 24 小时；`messageRecallMinutes` 仅保留消息编辑语义。下方测试记录为群功能完成时的结果，私聊后续实现与重跑结果见 [私聊撤回验证记录](DIRECT_RECALL_POLICY_VALIDATION_2026-09-02.md)。

## 配置与行为

- 后台「系统设置 → 消息、撤回与文件 → 群聊撤回时限（分钟）」对应 `im_settings.groupRecallMinutes`，默认 1440，范围 1–10080。沿用确认、理由、权限和审计；无需新增表或迁移，数据库版本保持 59。
- 群主/管理员可撤回所有成员（含其他管理员及群主）的消息，普通成员只能撤回自己消息。服务端锁定并检查当前有效成员身份及群历史访问边界，按服务器发送时间计算时限，等于时限允许。
- 独立的 `messageRecallMinutes` 继续约束单聊撤回和编辑。后台审核撤回仍走原独立管理接口，不套用 App 群撤回时限。
- 重复撤回不重复写扩展或发送事件。过期、系统提示不能通过 App 撤回。保留扩展与全员 CMD，WuKongIM 原文不物理删除。

## 仅调整展示，不提供管理消息保密性

四端共享 `group_message_policy.dart`，按当前成员角色过滤下列事件：

- 所有 `recalled` 占位（含后台全端撤回）。
- `group.invite.accepted/rejected/cancelled`。
- `group.member.joined`、`group.members.added`、旧 `group.member_added`。
- `group.member.leave/remove`、`group.blacklist.added`。

不匹配中文文案；公告、资料、禁言、角色变更和个人待处理邀请保持原行为。聊天列表、搜索、引用、收藏/置顶展示、摘要及通知使用同一判断。普通成员不显示撤回占位或空行；没有可见历史时摘要为「打开会话查看消息」。

不删除隐藏事件缓存。断线/群变更通知期间暂停信任群角色，重新获取后恢复；降级隐藏、晋升重新显示本人有权读取的原历史。分页使用原始序号，整页都是隐藏事件时继续请求旧页。客户端记录撤回终态，旧同步、延迟 ACK 不得恢复正文。

离线展示推送在 Webhook 入队时按角色筛选，投递前再次查询当前成员角色和撤回状态；查询失败重试，不放行。原始 IM 消息和 CMD 不裁剪，旧客户端及已展示的通知不保证追溯隐藏。
