# 独立企业多租户实施记录

## 状态：本机平台 + 默认企业及统一登录 Web 已运行，生产闭环仍未完成

本分支仅实施、验证本地代码；没有连接现网执行迁移、导入真实账号、
购买资源、修改现网部署配置、提交、推送或发布。仍保留现有单企业客户端入口。
本机已通过专用 Compose 运行新的平台及唯一默认企业，详见 `infra/tenancy/README.md`。

阶段 33 已提供显式、严格校验的 dedicated-host 生产运行包；不是直接删除预览保护。
本机持久环境仍使用 `development/local_preview`，企业托管预览仍要求
`IM_ENV=development`、`IM_TENANCY_PREVIEW=true`；**不允许固定验证码或 `IM_DEV_MODE`**。
生产包、本机实际验证及外部验收边界见 [生产运行手册](MULTITENANT_PRODUCTION_RUNBOOK.md)。
平台灾备、默认企业受控迁移及剩余故障闭环未完成前，不宣称全部生产代码已完成。

## 已实现的基础代码

- 独立 `server/cmd/platform`，独立平台 PostgreSQL schema，不启动业务、媒体、IM 服务。
- 数据库双向检查：平台拒绝业务库；业务服务拒绝平台库。
- 平台手机号唯一目录、密码哈希、认证会话、企业归属、企业码哈希、审计和持久任务。
- 平台密码登录、真实 OTP webhook、验证码首次开户、刷新令牌轮换与注销。
  未配置真实 OTP 时不开放 OTP 登录/注册能力；没有固定验证码实现。
- 60 秒一次性票据，绑定企业、本地身份和归属版本；只保存票据哈希。
  消费与账号状态检查同事务，错误企业、过期或重复消费拒绝。
- 注册预留 → 企业准备身份 → 激活归属，创建中返回 HTTP 202，不假报成功。
- 调换任务：源撤权 → 目标准备 → 激活；租约、幂等操作号、失败退避和审计。
  源操作未确认不推进；调回原企业仍使用新的本地用户 ID。
- 企业迁移 73：数据库身份绑定、平台账号关联、归属版本、本地身份状态、操作记录。
  手机号唯一性限定于非退休身份，旧身份保留原用户 ID 和历史数据。
- 企业迁移 74：独立认证版本、改密撤权中状态及幂等操作记录；平台 schema 4 增加持久密码任务。
  改密不调换企业、不退休本地身份、不更换用户 ID；好友、群组、历史记录保持原身份关联。
- 企业迁移 75：通话信令握手的持久未确认记录；只保存身份代次，不保存 Token、SDP 或媒体。
  握手结果不确定时禁止确认撤权，不按超时静默释放；故障记录的受控恢复工具仍待完成。
- 平台 schema 5：用途隔离的短信找回挑战、错误次数及一次性消费；6 位随机验证码仅保存 HMAC，
  挑战绑定账号/归属/认证版本。验证码 10 分钟有效，最多 5 次错误；独立手机号/连接来源限流，
  Redis 不可用拒绝发送。真实短信接口可配置，默认本机不启用，不添加固定验证码回退。
- 平台 schema 6 / 企业迁移 76：独立全局封禁状态、持久封禁/解封任务和企业幂等操作记录。
  受理立即禁止平台登录，已有开户/调换/改密先安全结束，再处理最终企业身份的撤权；
  企业 API、IM 与通话撤权确认前不标记完成。解封只恢复同一本地身份，不解除企业自己的封禁。
- 平台 schema 7 / 企业迁移 77：企业停用/恢复的持久任务、独立访问代次与分批撤权。
  受理停用立即阻止平台新登录，企业冻结业务入口、清理会话及推送绑定、分批踢线；
  确认丢失或依赖失败保留处理中。恢复前重新检查企业依赖，不恢复旧凭据或解除个人封禁。
  已受理开户/调换的激活阶段等待企业恢复；进度提交失败按原任务退避，不提前报告成功。
- 托管 IM 凭据绑定企业、平台账号、本地身份、归属版本、认证版本、企业访问代次及设备类型。
  改密、解封及企业恢复后不重新安装旧 IM Token；普通续期保持当前代次凭据稳定。
  本地专用 IM 镜像另修复强制断开先删连接索引导致 socket 遗留、认证失败不关闭连接的问题；
  使用固定源码/补丁摘要构建，未改生产镜像，详见 `infra/tenancy/Dockerfile.im`。
- 企业 `/v2/auth/tenant-session`、本地身份校验、企业 JWT 标识及归属版本校验。
- 独立 mTLS 控制监听器，不接受转发头冒充身份。证书使用独立 CA 和唯一 URI SAN：
  `spiffe://frogim/platform`、`spiffe://frogim/tenant/<id>`。
- 企业准备、撤权操作；先永久停用业务身份和刷新会话，再替换三类 IM 凭据、
  踢出连接、查询离线状态，并移除及确认本用户的 LiveKit 参与者，最后确认撤权。
  会话签发、通话握手与撤权使用数据库锁协调；公共通话入口实时检查身份和认证版本，
  拒绝旧 JWT 重连。只代理企业自己的 RTC 信令，媒体流与普通业务不经过平台服务器。
- 平台管理接口：独立管理员账号/会话、企业登记/列表、企业码创建/启停、调换、任务列表。
  企业内 `platform_admin` 无法成为平台管理员。
- 平台 schema 8：Android/iOS/Web/macOS 统一版本策略、不可变发布历史与事务审计。
  灰度按安装标识稳定分桶，低于最低版本始终强制；默认四个平台策略停用，不自动发布安装包。
  平台独立运营管理员填写理由并确认，稳定请求号处理丢失响应，版本冲突不覆盖；企业后台无权写入。
- 平台 schema 9：独立平台管理员生命周期与幂等操作结果；账号名忽略大小写唯一。
  运营管理员可新增、启停、改角色及重置其他管理员密码；本人修改密码要求当前密码，
  只读管理员只可查看及修改自己的密码。账号、会话撤销、操作结果及无密码审计同事务。
  禁止修改本人的启停/角色，管理员变更串行且保留至少一个启用的运营管理员。
- 平台 schema 10：推送设备加密绑定、会话续期/退出联动、路由元数据摘要及逐设备提交结果。
  平台侧已提供认证绑定与 mTLS 投递接口、个推及 APNs VoIP 适配，企业不能传入设备令牌或正文。
  企业队列已通过 mTLS 代理接线；Flutter 个推登记已转到平台；本机保持推送关闭。
- 平台 schema 11：Web Push 订阅按端点保持唯一归属，密文凭据变化独立增加绑定版本。
  平台配置校验 VAPID 密钥对、精确 HTTPS 供应商域名和订阅密钥；投递拒绝内网与重定向。
  Flutter Web 登记使用平台会话，独立后台脚本按身份、绑定版本和平台会话有效期过滤通知。
  换号、退出、过期和关闭页面后的点击交接已有代码与隔离测试；真实浏览器实收尚未验收。
- 平台 schema 12：服务器与企业的一对一绑定、唯一主机标识、校验版本和不可变操作回执。
  平台后台可选择运维预配置的代理登记/重新校验；不接收控制地址、私钥或 Shell 命令。
  独立代理证书身份 `spiffe://frogim/agent/<id>`；默认仅开放 mTLS 检查，执行能力须运维显式配置。
  查询代理后重新校验管理员会话、企业配置及服务器版本，审计失败整笔回滚。
- 平台 schema 13 / 企业迁移 79：默认企业历史账号导入批次、逐账号租约任务、源身份绑定回执
  与临时封禁到期任务。已实现本机离线导入命令，原用户 ID 和业务引用不变，密码哈希仅进入平台
  认证账号表，源哈希在成功绑定时清空。撤权确认前账号不可登录，完成后不自动恢复企业服务。
  预留、绑定、撤权和完成可以分别中断恢复；旧部署接管、网络切换及旧客户端兼容仍待实现。
- 平台 schema 14：持久部署任务、不可变发布/绑定快照、显式重试回执、维护互斥与事务审计。
  已接入独立代理控制、容器回执及企业业务/停用状态核验；后台增加部署任务页。
  默认本机代理仍没有执行配置或 Docker socket。新增九服务完整本机企业包及实际部署/升级/
  同 schema 回滚、代理 journal 重启演练；平台任务到完整栈的整链故障演练已验证。
  已增加加密冷备份与新卷恢复核心及本机九服务演练；自动维护编排、异地备份与灾难接管仍待补齐。
- 企业迁移 78：推送入队时冻结企业、账号、本地身份、归属/认证/企业访问版本与到期时间。
  单条、离线消息批量及公告批量入队共用数据库触发器；不能在重试时换上新的身份版本。
  托管企业不读取本地设备令牌、不接收新的旧式推送登记，只能停用推送或通过平台控制连接投递。
- 独立平台后台入口及独立构建：企业目录、服务器资源、部署任务、账号归属、邀请码、身份任务、封禁任务、企业启停任务、客户端版本、平台管理员、审计十一个页面；
  只读角色、分页筛选、理由与确认、失败保留表单、一次性显示邀请码、会话失效清屏。
  平台 token 只保存在页面内存；企业后台页面、token 和构建产物互不复用。
- 任务错误分类：明确的群主/注册策略/邀请码错误进入 blocked，不无限重试；
  网络或撤权未确认继续原操作号退避重试。支持同阶段受控重试，及已明确失败的注册邀请码修正。
  正在执行、阶段已变化、网络结果不确定的准备任务不允许改写注册资料。
- 调换增加源企业只读前置检查；群主未转让或源企业不可达时，不先停用平台登录。
  前置检查后仍在事务中检查身份版本；撤权时再检查群主身份，不把前置检查当作最终授权。
- 注册完成接口通过一次性 pollToken 发放平台会话与企业票据，不重新使用已消费的 OTP。
  凭据 24 小时过期，领取只成功一次；企业后台开户不生成 pollToken，不可领取用户登录会话。
- 企业后台单个/批量开户接入平台 mTLS 目录：企业范围由服务证书确定，仍校验本地
  `users.write`、理由与确认。平台账号、任务、请求号和审计同事务创建；请求号重试不重复开户。
  跨企业手机号冲突只返回“此号码不可开户”，不披露对方企业；不会退回本地建立密码账号。
  批量最多 100 行、4 个并发，逐行区分已开通、开通中、失败及结果未确认。
  后台显示本企业最近 100 笔开户任务，可手动刷新，未知结果可使用原请求号重试；
  未确认的初始密码只暂留当前页面内存，已受理即清除，不写入浏览器持久存储或任务。
  企业准备身份时仍校验密码长度策略；后台开户豁免公开注册开关和个人邀请码，自动生成个人码。
- 平台已提供登录态验证旧密码的修改接口、企业后台受控重置接口及任务查询。
  在平台暂停登录/刷新/票据后，企业撤销 API/刷新会话、推送绑定及三类 IM 凭据，确认 IM 离线后
  才启用新密码。任务失败保留原操作号；重复完成 ACK 不会撤销新会话。
  密码哈希只在平台认证库保存，不发送给企业，不写入审计或接口响应。
  企业后台用户详情提供重置入口、理由、二次确认、状态刷新及未知结果原请求重试；
  仅 `users.write` 可以提交，只能操作本企业当前本地身份。后台管理员自身密码仍属独立身份域。
- Flutter 账号安全已接入当前密码验证的统一改密，登录页区分未确认、处理中、完成和查询过期。
  提交前加密保存原请求号及查询凭据，不保存密码；超时后可重启恢复并按请求号查询，不自动重发。
  平台安全存储不可用时拒绝发起操作；密钥暂不可读时保留原加密记录，不误当损坏缓存删除。
  迟到查询、退出和账号切换受会话栅栏限制，新登录成功后清除旧账号的本机任务提示。
- Flutter 认证基础组件补充注册任务查询、完成领取、公开策略、验证码请求、企业码校验与注销；
  pollToken 只发送给平台，不进入 URL、不转交企业，迟到响应受会话栅栏保护。
- 本地可复现隔离测试栈和 PowerShell 7 测试脚本：三个 PostgreSQL、Redis、两个固定源码构建的 IM、
  两个固定镜像 LiveKit；后者仅开放主机回环的信令测试端口。
  真实 mTLS 平台认证/企业会话/调换链路通过；没有使用现网服务或固定 OTP。
- 媒体签名密钥拆分：`IM_MEDIA_SIGNING_SECRET`；可配置
  `IM_LEGACY_MEDIA_SIGNING_SECRET` 验证旧地址。不启用新配置时保持原地址签名。
- Flutter `TenantContext`、独立认证交换客户端、异步归属栅栏、不可变缓存命名空间。
  新缓存与原单企业缓存使用不同前缀，清理任一企业缓存不删除其他企业缓存。
- Flutter 登录/注册页接入平台认证，企业邀请码与个人邀请码分开，待开户任务可重启后继续查询。
  未配置真实 OTP 时只展示密码登录；平台扫码登录尚未完成，暂不显示旧认证入口。
  平台短信找回已接入独立用途的真实短信发送适配器，未配置时入口关闭，不复用登录验证码。
- `PlatformImRepository` 按平台返回地址建立不可变企业业务连接；平台刷新令牌不发给企业，
  企业凭据不发给平台。续期、恢复、退出、归属变更与迟到响应均有会话栅栏；
  平台暂不可用时仅允许原未到期业务会话，不能延长有效期或回退默认企业。
- 本地凭据、业务缓存、草稿与原生 SDK 数据库使用企业/本地用户/归属版本命名空间。
  Web SDK 在会话结束时重建共享管理器、清理队列/回执/频道缓存；原生 SDK 注销清理
  重发队列和频道内存缓存，拒绝旧频道查询回调。网关在异步返回后检查是否已销毁。
- 头像相对地址使用当前企业，头像缓存键及前台通知携带会话范围；客户端版本查询指向平台。
  平台版本策略与公共查询已接入；中央推送平台、企业队列及 Flutter 个推登记已接线。
  设备登记/解绑与平台续期、改密串行，退出先阻断迟到回调；不登记旧企业推送绑定。
  通知检查企业、本地用户、归属/认证/企业访问代次及有效期。Web Push 已接线并有隔离测试，
  原生来电尚未完成，真实供应商与浏览器/手机实收未验收。
- 本机公开 HTTPS 使用 ECDSA P-256（Flutter TLS 实测兼容）；新增公开证书换发及备份工具，
  不改系统信任、不改控制证书、账号、密码或数据库。

## 本地接口边界

平台公开认证：`/v2/config/auth`、`/v2/auth/code`、`/v2/auth/login`、
`/v2/auth/password-login`、`/v2/auth/register`、`/v2/auth/refresh`、
`/v2/auth/logout`、`/v2/auth/enterprise-codes/validate`、
`/v2/auth/registration-jobs/{id}`、`POST /v2/auth/registration-jobs/{id}/complete`、
`POST /v2/auth/password-change`、`POST /v2/auth/password-change/status`、
`GET /v2/auth/credential-jobs/{id}`、`POST /v2/auth/password-reset/code`、
`POST /v2/auth/password-reset`、`POST /v2/auth/password-reset/status`。

公共客户端更新查询：`GET /v2/config/version?platform=android&version=1.0.12&installId=...`，
无需用户登录；返回原客户端兼容的 `data` 结构，响应不可缓存。存储不可用返回明确 503，
不返回虚假的“无更新”。默认停用的策略返回无更新，不复制企业历史更新配置。
版本管理：`GET /platform/admin/client-versions`、`GET /platform/admin/client-versions/{platform}/history`、
`PUT /platform/admin/client-versions/{platform}`；写操作需要 `requestId`、`expectedRevision`、理由与确认。
托管企业的旧版本查询/管理入口返回 409 `PLATFORM_VERSION_MANAGEMENT_REQUIRED`；单企业旧模式不变。
分发地址要求不带凭据、查询参数或片段的 HTTPS 地址；不下载或检查包签名，不启用临时签名链接。

管理员：`GET /platform/admin/administrators` 分页/账号/状态筛选；
`POST /platform/admin/administrators/operations` 统一处理 `create/access/password`，
携带稳定请求号、目标、观察到的认证版本、理由与确认；本人改密还需当前密码。
`GET /platform/admin/administrators/operations/{requestId}` 仅查询当前操作者自己的已提交结果，
不包含密码或哈希。本人改密后旧会话失效，响应丢失时需使用新密码重新登录再查询结果。
新密码至少 12 个字符、至多 72 个 UTF-8 字节；不自动生成或通过其他渠道发送密码。
平台管理员的撤权阻止其后续请求，但不取消此前已受理的身份、封禁、企业启停等持久任务。

平台运营基础接口使用 `/platform/admin/*`。与企业 `/v2/admin/*` 不是同一身份域。
封禁使用 `POST /platform/admin/accounts/{id}/access`，要求运营管理员、稳定 `requestId`、
观察到的 `expectedAuthVersion`、`blocked`、理由和确认。返回 202 不等于企业撤权完成。
`GET /platform/admin/access-jobs` 支持企业/阶段及账号、请求号、任务号精确查询；只读管理员可查询。
企业启停使用 `POST /platform/admin/tenants/{id}/access`，要求独立运营管理员、稳定 `requestId`、
`expectedAccessVersion`、`enabled`、理由与确认；`GET /platform/admin/realm-jobs` 查询进度。
停用/恢复均返回任务受理，只有企业分批确认及平台审计提交后才变为最终状态。
注册任务查询使用响应中的随机 pollToken Bearer 凭据，不放在 URL 查询参数里。
票据消费和企业身份控制仅通过专门的 mTLS 监听器；不要在公网网关代理 `/internal/*`。

企业普通 API、媒体、WuKongIM TCP/WSS、LiveKit 都继续直达本企业；平台没有业务反向代理。

企业后台开户沿用 `POST /v2/admin/users` 和 `/v2/admin/users/batch`；托管模式必须携带
`requestId`，单个返回 202 + `item.jobId`，不是可登录的 UserRecord。
`GET /v2/admin/users/provisioning-jobs?jobId=` 返回本企业后台开户任务；旧后台需随服务端升级。
内部开户/查询为 `/internal/tenancy/admin/accounts`、`/internal/tenancy/admin/account-jobs`，
仅独立 mTLS 监听器可达，不在公网配置路由。当前平台 schema 为 10，企业 schema 为 77。

平台推送基础接口：`GET /v2/config/push`、`POST /v2/push/devices`、
`POST /v2/push/devices/unbind`；绑定/解绑使用平台刷新凭据，不接受企业 JWT、账号或企业 ID。
私有 `POST /internal/tenancy/push/deliver` 从已验证的企业服务证书获得企业身份，
仅接收目标身份代次、事件类型、路由 ID 和有效期，不接受设备令牌、URL 或消息正文。
平台只保存请求摘要及最初接收设备，不重试时追加新设备；成功数表示供应商已受理，
不是手机已收取。超时后的实际投递不可回滚，使用稳定供应商请求 ID，但不承诺端到端恰好一次。

企业 `GET /livekit/rtc`、`/livekit/rtc/validate` 及对应 `/rtc/v1` 路径只接受本企业签发的
通话专用凭据，并检查当前身份、认证版本及通话参与状态。不开放 LiveKit Twirp 管理接口；
LiveKit 原始 7880 端口必须保持企业私网专用，不能绕过本企业入口。默认企业迁移前的旧
通话凭据不适用该新模式；正式迁移须结束旧活动通话再切换，不能承诺旧凭据无感兼容。

## 阶段 30：Web 跨标签页凭据与离线恢复收尾

- 原平台队列只在单个 repository 内串行，多个页面可同时消耗同一轮转令牌；旧页面退出还
  可能清除其他页面的新登录。现 Web 使用平台入口范围的浏览器 Web Locks，登录、刷新、
  登记/解绑设备、改密与共享凭据清理按同一锁序执行。排队最长 20 秒，开始执行后不因排队
  超时提前释放锁；不可用时明确失败，不回退为无锁请求。原生端保留进程内队列。
- 每次实际凭据 RPC 前在锁内重读加密状态；同登录代次只采纳最新平台令牌，不采纳其他
  页面的业务到期时间。每次新登录生成随机代次，包括同账号重新登录。旧代次退出/过期
  不能删除或注销新代次。异步事件只携带随机标记，另有回到前台及 3 秒补查；通知不是授权
  来源。锁或存储失败仍同步隔离本页请求并完成本页连接清理，不盲删共享状态。
- 业务会话、标签页登录快照、待开户及改密查询能力使用加密 sessionStorage；平台轮转
  令牌仍共享。加密密钥首次创建使用独立浏览器锁，暂时无法读取密钥时不生成替代密钥或
  删除原密文。退出清除本页业务凭据和登录快照，不删除另一页面的会话。
- 临时平台故障仅可恢复本页同代次且仍有效的业务凭据。额外核对本页业务 JWT 的版本及
