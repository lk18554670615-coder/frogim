# 群成员预览与发送者资料修复（2026-09-03）

## 根因

会话接口的 `memberCount` 是总人数，`members` 是最多 8 人的性能预览。客户端把该预览同时用于聊天信息成员区、消息昵称、头像点击和 @ 选择；WuKong 消息映射中的昵称默认空，预览之外的非好友因此显示“对方”，头像点击也被置空。

完整成员分页接口已存在。此前发言权限、群管理虽然加载完整成员，但没有把结果提供给聊天页共用。服务端 8 人预览属于既有性能设计，不需要取消。

## 修复

- 新增独立的内存成员目录，将完整成员与会话预览分离。复用原完整成员分页调用，按 ID 建索引，最多缓存 32 个群；一分钟内普通读取复用缓存，管理/邀请的显式刷新仍强制读取。
- 同群并发请求合并，失败不缓存部分列表。退出账号、销毁、重连及群成员/角色变更使对应结果失效；迟到请求不能恢复被移除的快照。会话刷新移除的群同步清理。
- 选择页加载过程中遇到重连/CMD 使请求失效时，在同账号下自动重取一次；不把正常的代际替换直接显示成加载失败，也不跨账号重试。
- 进入聊天复用已有发言权限查询加载成员，无需为每条消息单独发请求。当前群的新发送者未命中时补查，按群合并并设置 10 秒失败/缺失重试间隔；失败不阻断消息接收。
- 昵称、头像、资料入口使用完整目录，保留好友备注优先和群昵称。资料未加载时头像仍能点击补查；失败明确提示，不永久禁用。不伪造已离群且无资料用户的身份。
- 聊天内引用、菜单预览、置顶和搜索的昵称解析带群上下文；@ 面板使用完整成员，保留普通成员不展示/搜索呱呱号的限制。
- 聊天信息仍使用简洁成员预览，超过预览范围时显示“查看全部 N 位成员”，直接进入已有完整成员列表，支持搜索和资料查看。加载失败保留预览及重试入口。
- 不修改服务端、数据库、WuKong 协议、消息正文或已有好友/群管理权限；不清理消息、草稿及用户数据。
