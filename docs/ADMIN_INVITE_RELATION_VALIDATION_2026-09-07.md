# 后台邀请来源补绑与改绑（2026-09-07）

## 使用方式

入口：用户管理 → 用户详情 → 账号资料 → 邀请来源管理。

- 无邀请关系时显示“补绑邀请来源”，已有关系时显示“修改邀请来源”。
- 输入新的有效邀请码及操作理由，点击“核对邀请码”，核对新邀请人资料后再次确认保存。
- 仅具有 `users.write` 权限的管理员可以修改；只读管理员只能查看。
- 不提供清空邀请来源，不修改用户自己的个人邀请码、历史代码或自主修改额度。
- 不改变普通用户的注册规则；后台可维护关系，普通用户仍不能自行补填或转移。
- 只接受有效的当前邀请码。封禁/注销邀请人、停用/退休/不存在的代码均拒绝；禁止自我邀请及循环关系。
- 相同代码重复请求不重复写入审计。其他管理员已修改关系时，旧版本请求返回冲突，请关闭弹窗并点击“刷新邀请来源”后重新核对。

## 接口与数据

`PUT /v2/admin/users/{id}/invite-relation`

```json
{
  "inviteCode": "NEWCODE88",
  "expectedVersion": 0,
  "reason": "用户申请纠正邀请来源",
  "confirmed": true
}
```

- `expectedVersion` 必填：未绑定为 0，已绑定取用户详情的 `invitation.bindingVersion`。
- 返回当前关系的代码 ID/代码、邀请人 ID、初次绑定方式/时间、最近变更时间、维护来源和版本。
- 用户详情增加 `boundCode`、`boundCodeId`、`bindingSource`、`bindingUpdatedAt`、`bindingVersion`。
- 邀请管理关系列表展示当前来源及初次绑定/最近变更时间，可筛选“后台补绑”。
- 数据库版本 **64 → 65**。关系表新增维护来源、更新时间、版本；原有关系以注册来源、原绑定时间、版本 1 回填。
- 已有关系改绑保留初次绑定方式和时间。原本未绑定的账号标记为 `registrationMethod=admin`（界面“后台补绑”），不伪造密码/验证码注册事实。
- `invite_relation.changed` 审计记录前后关系、版本、操作者、理由；与关系变更同事务，审计失败时全部回滚。
- 后台关系改写通过事务级 advisory lock 串行化，阻止跨用户并发形成环。用户行与代码锁稳定账号状态、代码有效性，兼容并发代码重置中的外键锁。
- 不新增普通 App 响应字段，不发送聊天消息，不自动加好友，不追溯修改此前注册审计。

## 已执行验证

- PostgreSQL 实测：补绑、改绑、大小写/空格规范化、个人码/次数不变、原绑定时间保留、重复提交、无效/停用/退休代码、封禁/注销邀请人、缺失账号、两级/多级循环拦截。
