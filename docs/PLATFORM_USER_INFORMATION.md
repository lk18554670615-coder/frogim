# 平台用户信息完善

2026-10-01 实现完成，本地功能及 1440px / 1024px 实际视觉验证通过，已发布服务器。

## 实现

- 用户列表展示受控头像预览、昵称、手机号、可复制的用户 ID、当前企业呱呱号、当前企业、企业账号数量，以及相互独立的全局封禁、企业状态、未完成操作和同步摘要。头像缺失或失败使用占位，不直接请求快照中的外部头像地址。
- 企业筛选区分当前归属与保留账号，另外支持全局封禁和未完成操作筛选。关键词覆盖手机号、ID、当前企业昵称和呱呱号，250ms 防抖，使用 POST，不写入 URL。企业、筛选范围、状态、分页和企业资料标签可保存在地址中。
- 资料抽屉区分全局身份与企业账号；企业名称为标签，默认选中当前企业，分别展示个人资料、搜索设置、封禁、注册及注销时间、版本、同步时间与异常。未同步字段不解释为空值或正常状态，企业不可达时保留快照并提示无法确认最新资料。
- 列表与详情请求取消并检查请求代次。新筛选尚未返回时不显示旧筛选结果；新用户尚未返回时不显示上一用户资料。关闭抽屉保留安全筛选和本页内关键词，直达、刷新和前进后退由现有平台地址恢复。
- 复用统一抽屉、操作确认、理由、只读权限和版本校验。没有增加资料编辑、活动采集、服务、数据表或同步任务，也不更改客户端登录数据结构、企业后台及企业资料来源。

## 接口

`POST /platform/admin/users/query` 保留 `query`、`tenant`、`page`，新增：

- `tenantScope`：`current`（缺省，按当前企业）或 `membership`（在目标企业保留账号）。
- `banned`：可选布尔值，缺省不筛选全局封禁。
- `pending`：可选布尔值，缺省不筛选未完成操作。

管理列表用户增加 `registeredAt`、`membershipCount` 和 `currentMembership`（`profileVersion`、`syncedAt`、`syncError`，缺失时为 null）。单次 SQL 批量读取，不逐用户查库或访问企业。旧 GET 查询及每页 100 条、hasMore 行为保留。

详情 `GET /platform/admin/users/{id}` 的 user 增加上述管理摘要，保留 memberships 和受控头像接口。管理数据不进入登录授权的 User 类型，接口不返回密码哈希或认证令牌。
