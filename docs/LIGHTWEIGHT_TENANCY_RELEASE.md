# 轻量平台现有服务器发布

目标为现有服务器 `18.163.165.233`，Web 先上线，企业原业务库增量接入。部署只有一个新增的平台容器；企业 API、Caddy、IM、LiveKit、MinIO、共享 PostgreSQL 和 Redis 保留。平台库为 `platform_light`，企业库为现网预检确认的 `single_main_33d9ea2`。平台后台 `/platform/`，企业后台 `/admin/`，Web `/app/`；认证地址为 `https://18.163.165.233/platform`，业务不经平台转发。

`infra/scripts/release-light-tenancy.py` 只在远程 Linux 上执行，逐阶段调用 `prepare → rehearse → freeze → adopt → open → check`。Windows 使用 PowerShell 7，通过已有严格主机验证 SSH 工具上传固化产物和调用脚本。发布根目录必须为 `/data/frogim/releases/light-*`。生产凭据由私有 `config/operator-input.json` 提供，禁止提交或输出；原企业后台凭据保持不变。

发布包包括固定版本 Go API、导入工具、平台后台和生产 Web（1.0.16+8022）。Web 使用 `/app/` 基址及固定平台地址，禁止混入回环地址与本机账号。平台以生产模式运行，单独显式配置 `IM_PLATFORM_FIXED_OTP_CODE`，覆盖注册、登录、找回密码及修改手机号；该配置不得与短信提供商同时启用。HTTPS、安全 Cookie、生产地址及推送配置检查保留；企业普通用户独立认证关闭，短信配置只由平台负责。私网控制证书要求双向 TLS。

导入工具 `light-tenancy-import` 提供 `preflight`、`import`、`verify` 和 `revoke`。来源与平台连接串仅在私有 JSON 中传入。导入保留原用户 ID、号码、密码哈希、有效封禁、个人资料和注册时间，创建企业成员快照及未激活身份映射；不新建或改写业务用户和关系。异常号码保留并禁用，无密码不补默认密码；已删除记录不获得平台身份，但建立禁用映射用于撤销残留 IM 凭据。重复执行只接受精确相同的记录，冲突不覆盖；目标企业开放后禁止重跑导入。

演练使用服务器在线快照的独立数据库，验证导入、重复运行、校对和恢复；业务核心表逐表计算数量与内容指纹。隔离数据库测试另覆盖确认丢失后的部分导入续跑、冲突、禁用状态和重复号码。正式切换先显示维护入口，停止全部业务写入并关闭 IM/通话，再完成最终备份。备份包括企业数据库、Redis、IM、媒体、配置和前版本回执，服务器本地加密保存并验证可解密读取；密钥独立保存，不要求下载到 Windows。

`adopt` 导入校对后在维护入口后启动平台和企业。`open` 通过现有企业撤权接口逐账号撤销业务、媒体、IM、推送和通话凭据，全部确认后才记录 `opening` 并激活企业。旧移动端认证明确提示使用 Web；版本查询桥接平台，移动端沿用实际已有版本记录，不宣称未发布 APK 已可下载。平台数据库另行保存开服前备份。

阶段、备份摘要、隔离演练结果、撤权回执、镜像及配置版本写入发布目录的 `ops`。发布后只检查健康、readiness、网页和静态资源，业务功能在隔离环境验证，不在线上试做企业或账号切换。证书续期原定时器继续使用，重载目标更新为现行 Caddy 配置。

仅在 `opening` 前允许受控回退；停止新服务后恢复本次企业数据库备份及原部署，不能恢复整个共享 PostgreSQL/Redis 实例。进入 `opening` 后，即使确认丢失也禁止自动回退，先停写、保存新增数据，再人工修复或恢复。回退可能要求客户端重新登录。媒体和历史消息原路径保留；未经另行安排不删除旧版本或本次备份。

上线后只读观察 24 小时：认证错误、未完成操作、推送失败、连接数、磁盘及容器健康；仅异常或结束时通知，缺失时段不计作无异常。Android、iOS、音视频和真实供应商实收留待后续验收。现有未提交的 `docs/SERVER_CUTOVER_20260930.md` 不纳入发布提交。
