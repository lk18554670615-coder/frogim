# 按用户授权的全端消息删除

## 交付范围

实现服务端、管理后台及 Flutter 共用逻辑；数据库版本由 61 升至 62。保留此前未提交的视频消息、固定媒体地址、PC 聊天对象登录 IP 修改。没有提交、推送、部署生产、生成 APK/IPA 或修改更新策略。

这是持久化逻辑删除，不是撤回，也不是物理擦除：WuKongIM 原文仍供后台审计，备份、导出副本、已经展示的系统通知及旧签名地址不承诺追溯清除。旧客户端必须升级才能完整执行新规则。

## 使用及权限

- 后台「用户管理 → 用户详情 → 账号资料」设置「允许全端删除消息」，默认关闭。修改需要 `users.write`、理由和二次确认，并记录修改前后状态。
- 授权用户在本人可访问的单聊中可删除自己或对方消息；普通群还必须是当前群主或管理员。没有后台授权的群主、管理员也不能使用。
- 单条长按/右键菜单及多选栏提供「为所有人删除」，与「删除本机记录」分开。无撤回时限；同一会话每次 1–100 条，不能一键清空云端会话。
- 系统消息、过期消息、未入队消息不允许删除；已撤回的占位允许进一步删除。群历史可见边界继续执行，业务频道、客服及系统通知不纳入此权限。
- 所有人聊天列表直接移除消息，不新增占位或聊天通知。离线设备重新连接后补齐删除扩展。

## 服务端与同步

- `im_users.can_delete_messages_for_everyone` 非空、默认 `false`；权限不接受普通用户资料接口写入。
- `PUT /v2/admin/users/{id}/message-permissions`：`canDeleteMessagesForEveryone`、`reason`、`confirmed`。
- `POST /v2/messages/delete-for-everyone`：`conversationId`、`messageIds`、`confirmed`；返回消息 ID 和版本。
- 权限、成员角色、群状态、消息索引及扩展按事务锁重新核验。整批原子提交，重复请求不增加删除事件。消息索引等待全批最多 750ms，未就绪时明确失败，不绕过校验。
- 删除标记独立保存在原消息扩展中：`deletedForEveryoneAt`、`deletedForEveryoneBy`、同步版本。扩展、审计和 Outbox 同事务提交；审计不复制正文。
- `messages.deleted` 经 WuKong CMD 通知；SDK 扩展使用 `is_mutual_deleted=1`，不借用 `revoke`。
- 权限更新 CMD 每次有效变更使用独立 `changeId`，避免「授权 → 撤权 → 再授权」被 Outbox 当成同一个事件；同一事件重试仍幂等。
- 普通客户端历史、搜索、详情、编辑记录、收藏、置顶、引用、转发源和最近摘要应用删除规则。删除状态查询失败不返回未过滤原文。连续被删页按原始序号继续向前查询。
- 清理置顶、提醒并校正未读；待发送推送发送前检查删除标记，删除事件不产生展示型离线推送。
- 图片、视频、封面及文件访问依据仍有效的业务引用重新授权；单纯保留旧频道绑定不能绕过删除。已完成逐条转发及合并转发仍是独立消息。合并转发保留项目现有摘要快照语义，不扩展其原有媒体能力。
- 后台消息检索及聊天记录显示「已全端删除」、操作者和时间，保留原有审计原文访问。

## 客户端

- 按账号持久化独立删除标记；页面缓存、WuKong 缓存、晚到历史及 ACK 合并受同一标记约束。删除状态同步先于确认消息缓存展示。
- 无法校验删除扩展时不展示未验证历史，仍保留草稿及待发送/失败消息。会话切换、重新连接后重新同步。
- 删除后清理列表、摘要、收藏和引用预览；相关图片预览及视频播放退出，不删除其他有效引用共用的媒体文件。
- 本地缓存失败不会将已提交成功的删除报告为服务端失败，也不会自动再次提交。旧账号的迟到响应不影响新账号。
- Android/iOS 通过完整 SDK 的远程扩展更新其消息缓存；Web 清理 JS SDK 最近消息和提醒缓存；macOS Easy SDK 使用共用业务缓存及删除标记。

## 真实本机联调

使用隔离的 `video-regression-*` PostgreSQL、MinIO、API、Web 和固定 WuKongIM `v2.2.5-20260422` 派生镜像；只操作明确的两名视频测试账号和测试群，未访问生产数据。

- API 实测：未授权拒绝；授权后删除双方消息；双方历史移除；SDK 扩展为 mutual-delete 而非 recall；重复请求版本不变；撤权后立即拒绝。
- 群实测：授权普通成员仍拒绝，群主可以删除成员消息；双方群历史更新。
- 媒体实测：新上传视频、JPEG 封面和直接封面资源删除前 Range 请求 `206`，唯一消息引用删除后双方均 `404`；有独立转发引用时继续 `206`。
- 后台实测：授权开关、理由确认、即时撤权，以及删除后仍能查询审计原文。
- Web 实操：右键单条删除、多选 2 条确认删除；无占位，摘要回退；另一端 API 删除通过 CMD 在当前页面直接生效。连续授权/撤权不刷新页面也能更新菜单；页面重新加载不恢复已删消息。
- 最后一轮 API 删除消息 ID：`2095560063451041792`、`2095560063480401920`，同步版本 `29`。独立逐条转发 `2095560064340234240`、视频转发 `2095560070124179456` 继续可读，合并摘要转发也保留。
- Web 多选验收删除 ID：`2095559173637836800`、`2095559173696557056`。
- 验收后两名测试用户权限均恢复关闭，临时测试管理员已禁用；本次启动的 5 个隔离容器及后台开发服务已停止，未清空测试库。

独立转发的媒体授权依赖现有异步 `msg.notify` 索引：在源消息刚删除、转发索引尚未到达的极短窗口内，媒体可能暂时拒绝访问；索引到达后恢复，测试使用最多 3 秒的有界等待确认，未放宽旧绑定权限。这不是已删除原消息恢复可读。

## 尚未实测及上线顺序
