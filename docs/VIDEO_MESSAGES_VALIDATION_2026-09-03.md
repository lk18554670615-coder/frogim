## 实现要点

- 两份 Caddy 配置仅在 `connect-src` 增加 `blob:`，其他限制不变。Web 的 XFile 读取需要该权限，不能只配置 `media-src blob:`。
- Web 使用真实视频元数据与 Canvas 截帧，不转码、不将 MOV/WebM 伪装成 MP4。原生继续使用现有 `video_compress 3.1.4` 压缩。
- 封面约取第 1 秒，短视频取中间位置；JPEG 最长边 640，截帧超时 8 秒。已核对固定插件源码：Android 缩略图位置单位为微秒，iOS/macOS 为秒。Apple 通过插件公开 channel 调用同一字节缩略图方法，以保留小数秒；未修改插件或增加依赖。
- 无法预览或处理时展示重试、取消和“作为文件发送”；文件降级保留原始字节，以 `application/octet-stream` 上传，不宣称损坏文件仍是有效视频。取消不入队，处理中重复操作不会重复入队。
- 上传阶段显示进度，100% 后显示“等待消息确认”，不能视为 SENDACK 成功。每个账号、clientMessageId、媒体部分保存独立加密上传检查点。已完成上传/完成确认可复用；刷新后未上传的本地文件丢失时提示重新选择。
- 消息类型继续为 WuKongIM 5，使用 `cover`、`second`，兼容 `duration`；缓存保存媒体 ID 和封面字段。设备路径和 Blob 不进入共享消息正文。
- 点击视频始终进入应用内播放器；按媒体 ID 解析新 URL，不直接使用缓存中的旧签名 URL。支持自动播放尝试、手动播放/暂停、进度拖动、缓冲和全屏；地址/加载错误最多自动刷新一次，随后由用户重试。不会自动切换到下载。
- 播放器退出时停止并释放资源，取消待执行的加载超时；清理 Blob 和当前进程生成的压缩临时文件，不删除原始相册文件。未完成的发送保留重试所需资源。

## 数据与权限

数据库版本 **61**，只为 `im_media` 增加可空的 `cover_media_id` 外键和索引。没有新增消息正文副本。

完成视频上传时校验封面为同一上传者、已完成的 JPEG；首次完成后封面不可替换，重复完成保持幂等。封面授权继承视频的单聊、群历史及转发关系，正文补全使用服务端保存的关联，不信任消息自报封面。媒体清理跳过仍被视频引用的封面。播放签名保留真实 MIME，并返回 `Content-Disposition: inline`；媒体地址响应含有效期。
